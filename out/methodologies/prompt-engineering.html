M09

M09 · Versioned Prompt System

Prompt 工程

让大模型稳定输出的系统方法

这套框架解决什么

Prompt 不是写几句提示词，而是版本管理、离线评测、灰度放量和回滚的系统工程。从京东 6 套 Agent Prompt 的实战中沉淀。

适用场景

需要让大模型在业务场景中稳定、可控、可迭代地输出

执行步骤

01

定义输出标准

产出:输出标准文档

先写清楚「好的输出长什么样」，包括格式、约束、禁止项，再写 Prompt

02

结构化 Prompt

产出:Prompt 初稿

按角色/任务/上下文/约束/示例/输出格式六段式组织，而非一段话堆给模型

03

版本管理

产出:Prompt 版本表

每次修改记录版本号、修改原因和评测结果，像管理代码一样管理 Prompt

04

离线评测

产出:评测对比报告

用黄金问题集跑 A/B 对比，量化准确率、完整性、拒答率，不靠感觉判断好坏

05

灰度与回滚

产出:灰度方案

小流量验证→逐步放量，准备 10 分钟回滚机制，线上指标异常立即回退

自检清单

有版本号和修改记录

有离线评测集

有明确的禁止项

有兜底/拒答逻辑

有回滚方案

实践案例

京东项目 6 套 Prompt 各有独立版本号和评测子集，一次 Prompt 优化导致优惠计算 Bad Case 上升，10 分钟内回滚到上一版本。

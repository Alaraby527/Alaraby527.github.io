M11 · Capability Boundary + HITL

Agent 设计

AI能做什么、不能做什么、出错怎么办

这套框架解决什么

Agent 设计的核心是定义能力边界和出错兜底：AI 能做什么、不能做什么、什么时候必须让人介入。

适用场景

设计多步推理、工具调用、多角色协作的 AI Agent

执行步骤

01

三维可行性评估

产出:能力边界定义

从技术可行性、业务可行性、数据可行性评估哪些环节适合 Agent 自主完成

02

参与模式划分

产出:参与模式矩阵

低风险自动执行、中风险建议+用户确认、高风险必须人机协作，按风险等级分级

03

工具链设计

产出:工具调用规范

定义 Agent 可调用的工具、调用顺序、失败重试和超时策略，全链路可追溯

04

兜底设计

产出:兜底方案

未命中拒答、工具失败转人工、多轮断裂时主动确认，每个失败路径都有出口

05

可观测性

产出:日志与看板

记录每步决策、工具调用和结果，Bad Case 可回放可归因

自检清单

能力边界有明确清单

高风险操作有人工确认

工具失败有兜底

未命中会拒答

全链路日志可追溯

实践案例

京东导购 Agent 按风险分三级：参数查询自动执行，推荐建议需确认，以旧换新/退换货必须转人工。
